# Codex AutoContinue

Приложение на C# / WPF / .NET 10 LTS для нативного Windows x64. Продолжает **конкретную локальную сессию Codex** после естественного восстановления обычных лимитов ChatGPT. CLI остаётся отдельной зависимостью.

## Запуск

Исправленная версия **1.0.1**: `artifacts\release-fixed\CodexAutoContinue.exe`. Предыдущая 1.0.0 остаётся в `artifacts\release`, поскольку она была запущена во время обновления. Для перехода нажмите в старой версии «Выход» (крестик может скрывать окно в трей), затем запустите новый EXE. При включённом автозапуске сохраните настройки из новой версии, чтобы обновить путь.

Публикация self-contained: устанавливать .NET для запуска не требуется. EXE можно перенести в постоянную папку; при включённом автозапуске не перемещайте его без повторного сохранения настройки.

1. Установите официальный Codex CLI: `npm install -g @openai/codex` (нужен Node.js). Выполните `codex login`, выберите вход через ChatGPT. Если CLI уже есть в расширении VS Code, приложение находит его нативный `codex.exe` автоматически. Путь можно изменить в настройках. Не передавайте приложению `auth.json` или токены.
2. Откройте приложение. В настройках проверьте подключение CLI и авторизацию ChatGPT.
3. Выберите папку проекта и новую задачу либо точную сессию через список / ID.
4. Для существующей сессии сначала остановите и закройте эту задачу в исходном клиенте Codex, затем отметьте подтверждение передачи и нажмите «Запустить». Если сессия остаётся занятой, сохраните работу и полностью закройте исходный клиент (например VS Code), после чего повторите передачу.
5. Оставьте включённым автопродолжение. При остановке по `usageLimitExceeded` приложение ждёт доступности всех исчерпанных окон. Нормальный ответ завершает цикл, последующие сообщения автоматически не отправляются.

«Приостановить» прерывает текущую работу и ставит ожидание на паузу. «Остановить» также отключает автоматическое восстановление. «Продолжить сейчас» заново проверяет лимиты, историю и блокировку сессии. Для вопроса Codex используйте «Ответ / уточнение»; запросы команд, файлов, дополнительных прав и подключённых сервисов находятся во вкладке разрешений. Никакое разрешение не принимается автоматически.

Окно можно скрыть в трей. Полный выход — кнопка «Выход» или пункт трея «Полный выход». Он завершает принадлежащий приложению App Server и его дочерние процессы. Ожидание лимита сохраняется; восстановление управляется отдельным переключателем. Для работы компьютер должен оставаться включённым. После сна происходит новая проверка.

## Ошибка `already has an active writer`

Эта ошибка означает, что сессию уже удерживает исполнитель Codex. Остановка генерации сама по себе может оставить сессию загруженной в исходном клиенте. App Server освобождает сессию по собственным правилам жизненного цикла; подробнее — [официальное описание выгрузки](https://learn.chatgpt.com/docs/app-server#unsubscribe-from-a-loaded-thread).

Версия 1.0.1 устраняет повторный `thread/resume` внутри одного подключения и отмечает передачу успешной только после получения сессии своим сервером. При внешнем конфликте автопродолжение отключается, показывается инструкция на русском, модельный запрос не отправляется. После освобождения сессии повторите явную передачу через «Локальная сессия». Сохранённая неподтверждённая передача из версии 1.0.0 также требует повторного подтверждения.

## Лимиты и безопасность запуска

- Протокол: официальный App Server, JSONL по stdin/stdout, `initialize` / `initialized`.
- Проверка: `account/read`, `account/rateLimits/read`, `thread/list`, `thread/read`, `thread/loaded/list`; выполнение: `thread/start`, `thread/resume`, `turn/start`, `turn/interrupt`.
- В установленной версии используется подтверждение `ordinaryUsageAllowed`. `null` не считается восстановлением. Старые полные ответы без этого поля допускаются только при однозначно доступных окнах и отсутствии серверных блокировок. Частичные уведомления не разрешают запуск: нужен новый ответ на чтение.
- Сбросы `resetsAt` показаны в локальном часовом поясе Windows. Ожидается самое позднее время **среди исчерпанных** окон. Истечение времени само по себе не доказывает восстановление. Проверка по умолчанию каждые 60 секунд, диапазон 30–900; неизвестные данные увеличивают интервал до 30 минут.
- API-ключи, сторонние провайдеры, покупка кредитов и потребление сохранённых сбросов не используются. Конфигурация Codex не изменяется; sandbox и approval policy не переопределяются.
- Неоднозначно принятый запуск блокируется. Его `clientUserMessageId` используется для сопоставления с историей, **не как обещание идемпотентности сервера**. Кнопка проверки истории может снять блокировку только после подтверждённого завершения соответствующего запуска. При отсутствии доказательств требуется проверка сессии в исходном клиенте.
- Собственные экземпляры защищены блокировкой приложения и файловой блокировкой по ID. Статус отдельного App Server **не доказывает отсутствие работы в VS Code**: явная передача обязательна.
- Дочерние процессы привязаны к Windows Job Object с `KILL_ON_JOB_CLOSE`, поэтому не остаются работать после полного выхода или аварийного завершения приложения.

## Хранение

`%LOCALAPPDATA%\CodexAutoContinue`: `state.json`, `events.log`, `locks\`. Исходное задание, точный ID, состояние и настройки записываются атомарно. Повреждённый JSON перемещается в `.corrupt-*`; автоматическое восстановление выключается. Журнал: 2 МБ + до 4 архивов, кнопка очистки в настройках. Полный текст исходного задания хранится локально; не включайте в него секреты. Содержимое файлов авторизации приложение не читает. Ответы на вопросы и сырой stderr не журналируются; известные форматы секретов в событиях и выводе скрываются. Вывод Codex отображается по завершённым элементам, без записи потоковых фрагментов в журнал.

Автозапуск — пользовательский ключ `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\CodexAutoContinue`. Отключение переключателя удаляет эту запись. Для удаления приложения сначала отключите автозапуск и выполните полный выход, затем удалите его папку; сохранённые данные удаляются отдельно по желанию.

## Сборка и проверки

В Windows PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
# Также проверить установленный CLI без запросов модели:
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Integration -CliPath 'C:\путь\к\codex.exe'
# Публикация в отдельную папку, если прежний EXE запущен:
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Integration -CliPath 'C:\путь\к\codex.exe' -OutputDirectory 'E:\путь\к\release-fixed'
```

Скрипт использует SDK .NET 10.0.401 (локальный или установленный), при отсутствии устанавливает его через официальный `dotnet-install.ps1` в `.sdk`. Выполняет сборку, консольный автоматический набор тестов, публикацию self-contained Windows x64 и тестовый запуск опубликованного EXE. Интернет нужен для SDK и пакетов публикации. Повторные проверки можно запустить отдельно:

```powershell
dotnet run --project tests\CodexAutoContinue.Tests -c Release
dotnet run --project tests\CodexAutoContinue.Tests -c Release -- --integration 'C:\путь\к\codex.exe'
```

Результаты: `artifacts\checks\tests.txt`, `integration.txt`, `ui-smoke.txt`, `sha256.txt` и снимки окна. Подробный отчёт: [docs/TEST-RESULTS.md](docs/TEST-RESULTS.md).

## Проверенная совместимость и ограничения

Проверено на Windows 11 Pro x64, .NET 10.0.12, SDK 10.0.401, `codex-cli 0.162.0-alpha.17.2`. Схемы этой версии сгенерированы самим CLI в `docs/protocol` и `docs/protocol-ts`.

Список установленного App Server действительно содержит локальные сессии VS Code; чтение истории по ID проверено без возобновления работы. Продолжение реализовано через `thread/resume` с тем же ID. Панель VS Code не управляется. Полный реальный цикл исчерпания и сброса лимита проверен имитацией; реальные лимиты аккаунта не исчерпывались, лишние модельные задачи не запускались.

Поддерживаются сессии того же нативного Windows CLI и того же `CODEX_HOME`. WSL, SSH, облачные задачи и другой профиль Codex не поддерживаются. Недоступный ID не заменяется похожей или «последней» сессией. Неопознанные запросы сервера отклоняются; неизвестные уведомления не запускают работу. В разных версиях CLI протокол может меняться, поэтому после обновления используйте проверку интеграции. Новые неизвестные данные трактуются осторожно.

Windows 10 x64 предусмотрен архитектурой WPF, но отдельная машина Windows 10 не проверялась. Официальная поддержка Microsoft для .NET 10 на Windows 10 ограничена поддерживаемыми LTSC/Enterprise выпусками. См. [поддерживаемые Windows](https://learn.microsoft.com/en-us/dotnet/core/install/windows) и [.NET LTS](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core).

Официальные источники: [App Server](https://learn.chatgpt.com/docs/app-server), [неинтерактивный режим](https://learn.chatgpt.com/docs/non-interactive-mode), [CLI reference](https://learn.chatgpt.com/docs/cli/reference).
